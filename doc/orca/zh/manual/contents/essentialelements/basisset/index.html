    基组（Basis Sets）¶

    ORCA 提供大量原生实现的轨道基组和辅助基组，以及可与之组合的各种有效核势（effective core potentials, ECP）。对于标量相对论方法（如 ZORA、DKH 或 X2C），也有专门的相对论基组可供使用。此外，还可以从外部文件读入其他基组。大多数内置基组和 ECP 取自 Basis Set Exchangebse2019 或其前身 EMSL 库，ORCA 中的输入格式与 "GAMESS-US" 格式密切相关。

    基本用法（Basic Usage）¶

    在 ORCA 中使用轨道基组和辅助基组最简单的方式是通过简单输入关键字。所有可用的轨道基组关键字见 basisset.builtin，所有辅助基组选项见 basisset.aux。例如，Karlsruhe def2-TZVP 基组可以通过 def2-TZVP 关键字调用。

    ! def2-TZVP

    注意

    有些基组（如 Karlsruhe def2）对重元素默认采用 ECP，此处为 def2-ECP。ECP 的显式控制见 basisset.ecps。

    分辨率恒等式（resolution-of-the-identity, RI）所需的辅助基组可以用同样的方式定义。本例中使用的是 Weigend 通用 def2/J 辅助基。

    ! def2-TZVP def2/J

    注意

    注意，许多计算中 RI 默认是开启的（例如杂化 DFT 默认使用 RIJCOSX）。相应地，若未另行指定，def2/J 辅助基也会自动调用。在标量相对论计算中，默认改为 SARC/J。

    注意，RI 的辅助基组有三个独立的槽位： - AuxJ 是 RI-J、RIJDX/RIJONX 和 RIJCOSX 近似所用的库仑拟合基。 - AuxJK 是 RI-JK 所用的库仑与交换拟合基。 - AuxC 用于后 SCF 动态电子相关方法中基于 RI 的积分生成步骤，例如 RI-MP2、DLPNO-MP2 和 DLPNO-CC。

    最后，F12 方法除了专用轨道基（以及可能的 AuxC）外，还需要互补辅助基组（complementary auxiliary basis set, CABS），例如：

    ! F12-RI-MP2 cc-pVDZ-F12 cc-pVDZ-F12-CABS cc-pVTZ-F12-MP2Fit

    用简单输入关键字指定辅助基组时，会将其分配到相应槽位。但每个基组槽位以及 ECP 都可以在 %basis 模块块中显式分配。例如，可以按这种方式把某个 "/JK" 基分配给 AuxJ。

    %basis
  Basis "def2-TZVP"         # The orbital expansion basis set
  ECP   "def2-ECP"          # Effective core potential
  AuxJ  "def2/J"            # RI-J auxiliary basis set
  AuxJK "def2/JK"           # RI-JK auxiliary basis set
  AuxC  "def2-TZVP/C"       # Auxiliary basis set for correlated 
                            # calculations, e.g. RI-MP2
  CABS  "cc-pVDZ-F12-OptRI" # complementary auxiliary basis set 
                            # for F12 calculations
end

    如有需要，所有基组都可以通过简单输入（例如 ! DECONTRACT）或带相应关键字的 %basis 模块块去收缩（decontract）。注意，如果你的基组来自一般收缩（general contraction），它会在多个收缩中包含重复的原始高斯函数。这些会被移除，只保留唯一的原始函数，因此不会有冗余问题。

    %basis
  DecontractBas   false  # if chosen "true" the program will
                         # decontract the orbital basis set
  DecontractAuxJ  false  # if "true" - decontract the AuxJ basis set
  DecontractAuxJK false  # if "true" - decontract the AuxJK basis set
  DecontractAuxC  false  # if "true" - decontract the AuxC basis set
  DecontractCABS  true   # if "false" - do not decontract the CABS
  Decontract      false  # if "true" - decontract all basis sets
end

    提示

    • 一般而言，基组可以分配给特定元素、分配给单个原子，甚至分配给结构片段。
    • 任何内置基组都可以通过 orca_exportbasis 工具导出。
    • 内置基组的参考文献通常打印在 ORCA 输出的开头，orca_exportbasis 也会给出。

    警告

    ORCA 对所有基组都使用纯 d 和 f 函数（5D 和 7F，而不是笛卡尔 6D 和 10F）。在与其他程序的结果作比较时需要考虑这一点，尤其是对于用笛卡尔 (6D) 函数优化的 Pople 型基组。

    轨道基组（Orbital Basis Sets）¶

    下面我们将概述来自不同家族的原生实现基组，如 Karlsruhe def2 和相关一致（correlation consistent）基组，并列出各自的元素覆盖范围。如果重元素需要 ECP，会在相应表格条目中注明，并在通过简单输入或 %basis 模块块中的 basis 关键字选择该基组时默认调用。

    Pople 基组（Pople Basis Sets）¶

    ORCA 中提供 Pople 基组家族的多种基组。所有可用的 Pople 型基组列于 tab:essentialelements.basisset.builtin.pople。

    Pople 基组的命名约定（Naming Convention of Pople Basis Sets）

    • * 或 (d) 在除 H 以外的所有原子上添加一组第一极化函数
    • ** 或 (d,p) 在所有原子上添加一组第一极化函数
    • 更多组合：(2d)、(2df)、(2d,p)、(2d,2p)、(2df,2p)、(2df,2pd)
    • "G" 前的 \(+\) 表示在除 H 以外的所有原子上包含弥散函数（例如 6-31\(+\)G）
    • "G" 前的 \(++\) 表示在所有原子上包含弥散函数。仅当已包含 H 极化时才有效，例如 6-31\(++\)G(d,p)

    Ahlrichs 基组（Ahlrichs Basis Sets）¶

    ORCA 中实现的较早的 Ahlrichs 基组包括全电子基组，以及对 Rb 以后所有元素自动采用 def-ECP 的基组。可用的 Ahlrichs 基组列于 tab:essentialelements.basisset.builtin.ahlrichs。相对论重收缩变体见 rel.ahlrichs。

    注意

    ORCA 的旧版本（ORCA <4.0）曾对 Rb-I 元素也使用下面这些双-\(\zeta\) 和三-\(\zeta\) 关键字加载全电子基组。Rb-I 基组源自 Turbomole 库的非相对论全电子基组（如 "TZVPAlls"）。这种自动替换现已弃用。不过我们暂时仍可通过在下面关键字前加前缀 "old-" 来复现该行为，例如 old-TZVP。

    def2-QZVP H--Rn def2-ECP (Rb--Rn) 带极化的价层四-\(\zeta\)。
    def2-QZVPP H--Rn def2-ECP (Rb--Rn) 双重极化的价层四-\(\zeta\)。

    def2-QZVPPD H--Rn def2-ECP (Rb--Rn) 用于性质计算的弥散 def2-QZVPP 基组

    使用 ANO 基组的高效计算（Efficient Calculations with ANO Basis Sets）¶

    通常 ANO 基组是"一般收缩"的，这意味着对 任何给定的角动量，所有原始函数都对所有基函数有贡献。 由于 ANO 的概念只有在底层原始函数集足够大时才有意义， 计算很容易变得非常昂贵，除非在积分求值 算法中采取特殊措施。ORCA 为 ANO 基组提供了特殊算法， 并为非相对论计算提供了精确的 ANO 基组。然而， 即便如此，积分求值仍然十分昂贵，只有把所有积分 存储在磁盘上并按需重复使用， 才能实现高效率。

    目前 ANO 的使用仅限于内置 ANO 基组。它们建立在 cc-pV6Z 原始函数之上，因此 计算需要相当长的时间。

    提示

    不建议用 ANO 进行几何优化；它们会非常低效。

    推荐按以下方式使用 ANO：

    ! ano-pVTZ Conv TightSCF CCSD(T)
%maxcore 2000 
* int 0 1
C  0 0 0    0   0   0
O  1 0 0  1.2   0   0
H  1 2 0  1.1 120   0
H  1 2 3  1.1 120 180
*

    这给出：

    ano-pVTZ:
E(SCF) = -113.920388785
E(corr)=   -0.427730189

    与 cc-pVTZ 的数值比较：

    cc-pVTZ:
E(SCF) = -113.911870901
E(corr)=   -0.421354947

    因此，基于 ANO 的 SCF 能量比同规模的 cc 基组低约 8--9 mEh，相关能 几乎低 2 mEh。 通常 ANO 的结果比 cc 结果更接近基组极限。 此外，ANO 数值的外推表现非常好（见章节 mdci.basissetextrapolation）

    重要的是，本任务中所有积分都被存储下来。取决于你的 体系和耐心，这在 300--500 个基函数以内是可行的。 ORCA 的相关模块已重写，能够高效处理这些 存储的积分。因此，我们本来也可以使用 本来也可以使用 ! MO-CCSD(T) 或 ! AO-CCSD(T)，两者都会表现良好。

    然而，生成和存储所有四指标积分的负担 很快会变得相当沉重。因此，ANO 基组与 RI-JK 技术 的组合特别强大和高效。例如：

    ! ano-pVTZ cc-pVTZ/JK RI-JK Conv TightSCF RI-CCSD(T)

    对 SCF 而言这非常有效，可以高效地进行大得多的基于 ANO 的 计算。RI-MP2 也可以用这种方式高效完成。 然而对于 CCSD(T) 这类更高阶的相关方法， 合乎逻辑的选择是 RI-CCSD(T)，但它明显比基于 AO 或 MO 的 CCSD(T) 效率低（大约慢两倍）。 因此 ORCA 实现了一种混合方法，用 RI 近似 来生成所有四指标积分。这通过 "RI-AO" 关键字完成：

    ! ano-pVTZ cc-pVTZ/JK RI-AO Conv TightSCF AO-CCSD(T)

    在这种情况下 AO-CCSD(T) 或 MO-CCSD(T) 都会工作良好。当然这 并不能解决四指标积分的存储瓶颈。 如果这成为真正的问题，就必须使用 RI-CCSD(T)。 在本例中总能量的误差小于 0.1 mEh。

    警告

    在常规 RI 计算中无法使用第二个拟合基组，否则会得到不一致的结果。因此请只使用一个辅助基组！

    辅助基组的自动生成（AutoAux）¶

    如果所选轨道基组没有可用的辅助基组，ORCA 可以用关键字 AutoAux 自动生成一个。它的指定方式与其他拟合基组相同：作为 %basis 模块块中 AuxJ/AuxJK/AuxC 变量的取值，或作为简单输入行中的单独关键字（此时三个 Aux 槽位都填入相同的拟合基组）。AutoAux 也可以分配给单个元素或原子——见章节 basisset.element 和 basisset.atom。生成的基组可用于库仑、交换和相关拟合，精度与优化的辅助基组相当，代价是体积最多大一倍。autoaux AutoAux 的可用设置及其默认值见 tab:essentialelements.basisset.keywords.block。

    注意

    ORCA 3.1 的生成流程有很大不同，不会产生相同的结果！为兼容起见，仍可通过在 %basis 模块块中设置 OldAutoAux true 访问旧版本。

    注意，如果轨道基组包含弥散函数（如 aug-cc-pVXZ 系列），AutoAux 拟合基可能包含（近）线性相关。此时库仑度量的 Cholesky 分解会失败，程序很可能崩溃。可以用 !PrintBasis 打印有问题的辅助基组，并手动移除最弥散的 s 和/或 p 函数，这通常能解决问题。也实现了另一种自动解决方案——见章节 basisset.lindep-pcd。

    有效核势（Effective Core Potentials）¶

    从 2.8.0 版本起，ORCA 支持有效核势 （ECP）。若涉及重元素，它们是标量相对论全电子 计算的良好替代方案。这适用于几何 优化和能量计算，但对性质计算可能并非如此。 calculations.

    为了减少计算量，通常高度收缩且 化学惰性的核基函数可以通过采用 ECP 来消除。 ECP 计算只包含"仅价层"基组，因此 服从冻结核近似。核轨道的贡献由一个 有效单电子算符 \(U^{\text{core} }\) 来描述，它替代了核 与价电子之间的相互作用，并考虑了 电子的不可分辨性。其径向部分 \(U_l(r)\) 一般表示为高斯函数的线性组合， 而角向依赖通过角动量投影算符 \(|S^l_m\rangle\) 引入。

    \[ U^{\text{core} } = U_L(r) + \sum\limits_{l=0}^{L-1} \sum\limits_{m=-l}^{l}\left|S^l_m \rangle \left[U_l(r) - U_L(r)\right]\langle S^l_m\right| \]
    \[ U_l = \sum\limits_k d_{kl}r^{n_{kl} } \exp (-\alpha_{kl}r^2) \]

    最大角动量 \(L\) 一般定义为 \(l_{\text{max} }^{\text{atom} } + 1\)。计算 ECP 积分 所需的参数 \(n_{kl}\)、\(\alpha_{kl}\) 和 \(d_{kl}\) 已由多位作者发表，其中包括著名的 Los Alamos（LANL）hay1985chem 和 Stuttgart--Dresden（SD） fuentealba1982chem,szentpaly1982chem,fuentealba1983phys,stoll1984chem,fuentealba1985phys,dolg1987chem,igel1988mol,dolg1989chem,schwerdtfeger1989chem,dolg1989theor,andrae1990theor,kaupp1991chem,kuechle1991mol,dolg1991chem,dolg1992chem,bergner1993mol,dolg1993phys,dolg1993theor,haeussermann1993mol,kuechle1994chem,nicklass1995chem,leininger1996chem,leininger1996chemlett,leininger1997chem,schautz1998theor,wang1998theor,metz2000chem,metz2000theor,martin2001chem,cao2001chem,stoll2002comput,cao2002molec,peterson2003chem,petersonEtAl2003chem,figgen2005chem,lim2005chem,peterson2005theor,yang2005theor,lim2006chem,peterson2006phys,peterson2007chem,moritz2007theor,moritz2008theor,huelsen2009theor,figgen2009chem,weigand2009theor 参数集。取决于 ECP 的具体参数化方式， 相对论效应可以以半经验方式包含到 原本非相对论的计算中。把 \(U^{\text{core} }\) 引入 电子哈密顿量会产生两类 ECP 积分：由最大 角动量势 \(U_L\) 产生的局域（或 type-1）积分， 以及由投影势项产生的半局域（或 type-2）积分。 ORCA 中这些积分的求值按照 Flores-Moreno 等人发表的方案进行 flores2006comput。

    ECP 参数的手动输入（Manual Input of ECP Parameters）¶
    

    要手动指定 ECP 参数，NewECP 关键字后跟
要输入 ECP 的元素、被替换的核
电子数（N_core）和最大角动量
（lmax）。ECP 规范通过给出构成角向相关
势 U\(_l\) 的各个壳层定义来完成。
    

    %basis 
    NewECP <element>
      N_core <number of core electrons>
      lmax <max. angular momentum>
      [shells]
    end
end

    

    对每个 ECP 壳层，首先要给出角动量 \(l\)，
然后是原始函数的数目。原始函数本身通过
给出序号以及指数 \(a_{kl}\)、展开系数 \(d_{kl}\)
和径向幂次 \(n_{kl}\) 的相应元组来指定。
    

    # ECP shell 
      l <number of primitives>
      1    a1l    d1l    n1l
      2    a2l    d2l    n3l
      ...

    

    以钒的 SD(10,MDF) 为例。该名称表示
一种 Stuttgart--Dresden 型 ECP，替换 10 个核电子，
源自对中性原子的相对论计算。它
由角动量为 s、p、d、f 的 4 个壳层组成。注意
f 壳层的展开系数为 0.0，因此对这个
有效核势完全没有贡献。这是所有 SD 势的典型特征
（但对于像 TURBOMOLE 这样不支持 ECP 任意角动量、
因而对原始参数集进行重收缩的程序包，
情况可能不同）。
    

    %basis 
  # ECP SD(10,MDF) for V 
  # M. Dolg, U. Wedig, H. Stoll, H. Preuss,
  # J. Chem. Phys. 86, 866 (1987).  
  NewECP V 
    N_core 10 
    lmax f 
    s 2 
      1      14.4900000000    178.4479710000  2 
      2       6.5240000000     19.8313750000  2 
    p 2 
      1      14.3000000000    109.5297630000  2 
      2       6.0210000000     12.5703100000  2 
    d 2 
      1      17.4800000000    -19.2196570000  2 
      2       5.7090000000     -0.6427750000  2 
    f 1 
      1       1.0000000000      0.0000000000  2 
  end
end

    

    ECP 与幽灵原子（ECPs and Ghost Atoms）¶
    

    当输入中定义了幽灵原子时（见章节 coordinates.special），默认不会为这些原子添加 ECP。如果确实需要，请在 %basis 模块块下添加 GhostECP true。
    

    %basis 
 GhostECP true
 AllowGhostECP true # synonym
end

    

    

    ECP 嵌入（ECP Embedding）¶
    

    簇模型的计算有时需要嵌入势，以考虑边界处 otherwise 被忽略的排斥项 giordano2001surf。为简化 ORCA 中的这类计算，ECP 嵌入可以很容易地完成：
    

    *xyz ...
# atom>  charge x    y    z    optional ECP declaration
Zr>      4.0    0.0  0.0  0.0  NewECP "SDD" end
...
*

    

    这种无核 ECP 中心在坐标部分声明，方法是在元素符号后附加尖括号 ">"。注意嵌入 ECP 在 ORCA 中按点电荷处理，因此接下来必须给出电荷。无核 ECP 中心的坐标照常指定，后面可以跟可选的 ECP 分配。一般而言，采用 ECP 嵌入流程的计算应为单点计算。但如果确需进行几何优化，请务必为无核 ECP 中心设置显式的笛卡尔约束。

    • ORCA 始终使用球谐高斯函数。
      •

      •

    %basis
  NewGTO 8    # new basis for oxygen
   "6-31G"
    D  1 
    1  0.4  1.0
  end
end

    

    本例中把 6-31G 基组分配给氧，并另外向氧的基组添加一个指数为 0.4 的极化函数。
    

    注意 NewGTO 关键字不会更改给定元素的 ECP——必须使用 NewECP 或 DelECP（见章节
basisset.ecps).

calculations:

                # oxygen

    1  0.8  1.0
  end

sets. The keywords NewAuxCGTO, AddAuxCGTO, NewAuxJKGTO,
AddAuxJKGTO、NewCABSGTO、AddCABSGTO 的用法相同。关键字 NewAuxGTO 和 AddAuxGTO 与 NewAuxJGTO 和 AddAuxJGTO 相同，即它们只影响库仑辅助基组
(AuxJ)!

    为片段分配基组和 ECP¶
    

    在多层级或 QM/QM 计算中，把不同基组分配给不同的片段可能更方便。这可以在 %basis 模块块中用关键字 FragBasis、FragAuxJ、FragAuxJK、FragAuxC、FragCABS 和 FragECP 完成，后跟片段编号（从 1 开始！）以及 ORCA 库中的标准基组或 ECP（见 basisset.builtin 和 table:ECP_keywords）。注意与 NewGTO 关键字不同，FragBasis 在适用时也会更改 ECP。片段基组会覆盖全局或按元素的选择（basisset.element），但可以被针对单个原子的设置（basisset.atom）覆盖。如果为片段请求了 AutoAux，它会针对每个原子实际选定的轨道基组生成，即使该基组在坐标部分被更改。但如果为某元素或在简单输入中请求了 AutoAux，辅助基组会在片段基组分配之前生成（这不是我们想要的），因此必须为片段再次请求 AutoAux。下面给出一个例子：

    线性相关（Linear Dependence）¶
    

    前面几节描述了如何从分子内不同位置（通常以原子为中心）
经过适当参数化的函数来构造所需的分子
基组。这些函数的参数化使得
出现冗余的可能性极小。然而，由于
我们只能在有限的数值精度下工作，而且
这些参数还依赖于分子几何结构，
冗余无法事先完全消除。冗余
是指在给定参数值（包括几何）下由给定基函数
张成的子空间，可以由更少数目的
线性无关基函数同样地张成。线性
相关（冗余）的函数集可能导致数值不稳定。
线性相关通常通过寻找重叠矩阵的
零本征值来识别。注意重叠矩阵
（或相关矩阵）的逆用于正交化，
因此如果接近零的本征值处理不当，
逆矩阵将失去良好定义，SCF 过程在数值上
变得不稳定。
    

    由前面的讨论可知，治疗线性相关的关键参数
是判定重叠本征值为零的阈值。
该参数可以用下面的关键字更改
    

    %scf
  sthresh 1e-6 # default 1e-7
end

    

    虽然上述参数的取值没有严格限制，
但合理的范围是 1e-5 到 1e-8 之间（默认为 1e-7）。取 1e-9 甚至更低也许能不出现
收敛问题，但结果有被接近零的向量
引起的噪声污染的风险。在困难情形下，1e-6 的阈值
往往工作顺畅，高于此值则有可能
丢弃越来越多的函数，这也会影响
与其他计算结果的可比性。要监视
小本征值的行为，应在输出中查找下面的
块
    

    Diagonalization of the overlap matrix:
Smallest eigenvalue                        ... -1.340e-17
Time for diagonalization                   ...    0.313 sec
Threshold for overlap eigenvalues          ... 1.000e-07
Number of eigenvalues below threshold      ... 1
Smallest eigenvalue above threshold        ... 6.013e-07
Time for construction of square roots      ...    0.073 sec
Total time needed                          ...    0.387 sec

    

    这里打印最小本征值、当前使用的
重叠阈值以及低于该阈值的函数数目（将被丢弃）。
建议做一致性检查：SCF 收敛后在轨道能量中
查找相同数目的零值。
注意对属于零本征值的函数不施加
任何能级移动！
    

    如果从基组中移除了冗余向量，
! MORead NoIter 只应与原计算中相同的
SThresh 一起使用，否则结果将
不一致。
! MORead 仍可与更改 SThresh 一起使用，
但需要若干次 SCF 迭代。
    

    

    近线性相关情形的自动调整¶
    

    从 ORCA6 起有一个名为 DiffSThresh 的关键字，它控制
在发现重叠矩阵小本征值时自动收紧积分
截断参数 Thresh 和 TCut。我们发现这对
某些使用弥散基组的计算很重要，当上面显示的
"Smallest eigenvalue" 低于该值时，这些参数被设为最小值
Thresh=1e-12 和 TCut=1e-13。如果截断已经比这更严格，
例如使用 !VeryTightSCF 时，则不会发生任何变化。
    

    我们凭经验发现这些是抑制噪声、
增强 SCF 过程稳健性的安全数值，因此默认强制执行。
默认值为 1e-6，如果不希望这种自动调整发生，可在输入中设置
%SCF DiffSThresh -1 END 将其关闭。
    

    

    冗余基函数的移除¶
    

    虽然上述方法通常能成功消除
轨道基组中的线性相关，但 RI 中使用的辅助基组
并非以同样的方式正交化。RI 线性方程组
是用辅助基组库仑度量的 Cholesky 分解（CD）求解的。
如果辅助基组冗余，CD 会失败，
程序通常会中止。ORCA 中实现的一个简单解
是对度量进行带主元的 Cholesky 分解（PCD），
在给定阈值处终止。然后在计算开始时
把对零空间有贡献的壳层从基组中移除。
这可以对任何基组按重叠度量或库仑度量
来请求。它最适合用库仑度量的
AuxJ/AuxJK/AuxC 基组。截断后的基组可以用
!PrintBasis 关键字检查。经常会出现某元素的
部分原子被移除函数、而其他原子保留的情况。只要
阈值足够低，即只移除真正冗余的函数，
这就不应影响结果的分子对称性。
    

    %basis
  PCDTrimBas   Overlap # Trim the orbital basis in the overlap metric
  PCDTrimAuxJ  Coulomb # Trim the AuxJ basis in the Coulomb metric
  PCDTrimAuxJK Coulomb # Trim the AuxJK basis in the Coulomb metric
  PCDTrimAuxC  Coulomb # Trim the AuxC basis in the Coulomb metric
  PCDThresh    -1      # Threshold for the PCD: chosen automatically if <0
end
