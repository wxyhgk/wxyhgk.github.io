    自动碎片化（Automated Fragmentation）¶

    ORCA 提供了一个非常通用的碎片化（fragmentation）算法，称为 Fragmentator。尽管它主要是为处理蛋白质等大型生化体系而设计的，用户对碎片化方案拥有完全的控制权。在此背景下，既可以定义自定义碎片库（fragment libraries），也可以使用内置库和碎片化流程。

    碎片化可以通过 %frag 块来控制，相应的碎片化流程通过 FragProc 定义。StoreFrags true 可用于将生成的碎片以 XYZ 格式保存到 basename.fragments.xyz 文件中。

    %frag
   FragProc Connectivity
   StoreFrags true
end

    注意 有些内置库可能过于特化而不适合一般用途，因此通常建议根据具体需求定制碎片库。

    提示 如果你只想检查碎片，可以通过在 %scf 块中额外定义 DryRun true 来避免完整的 SCF 计算。

    例 1：磺基环丙沙星（Sulfociprofloxacin）¶

    环丙沙星（Ciprofloxacin）是一种强效广谱抗生素，属于氟喹诺酮类。在这个例子中，我们将把 ORCA 的自动碎片化工具与自定义碎片库一起用于环丙沙星衍生物磺基环丙沙星（PubChem: 128781），该分子带有许多不同的官能团。

    图：从 PubChem 数据库提取的磺基环丙沙星分子结构。

    现在我们可以使用 %frag 块开始对示例分子进行碎片化。由于我们想使用自定义的碎片库，我们定义 FragProc Extlib，并通过 XZYFRAGLIB "CustomLib.xyz" 提供库文件的名称。为了不进行完整的 DFT 计算，我们在 %scf 块中使用 DryRun true 设置。
    

    !PBE def2-SVP

%scf
   DryRun true
end

%frag
   PrintLevel      3
   StoreFrags      true
   FragProc        Extlib
   XZYFRAGLIB      "CustomLib.xyz"
end

*xyzfile 0 1 sulfociprofloxacin.xyz

    

    通过设置 StoreFrags true，我们把所有识别出的碎片保存到了多结构 xyz 文件 basename.fragments.xyz 中。此外，所有识别出的碎片也都记录在 ORCA 输出文件 basename.out 中。

    从碎片化运行生成 ORCA 输入——PrintInputFrags¶
    

    有时，从上一次运行自动生成 ORCA 原生碎片化输入是很有用的，这样可以更灵活地修改指认，例如当相同的基团需要被分配到不同碎片时。为此，可以使用 %frag 块中的 PrintInputFrags 关键词。
    

    !PBE def2-SVP

%scf
   DryRun true
end

%frag
   PrintLevel      3
   StoreFrags      true
   FragProc        Extlib
   XZYFRAGLIB      "CustomLib.xyz"
   PrintInputFrags true
end

*xyzfile 0 1 sulfociprofloxacin.xyz

    

    在之前所用的输入中加入相应关键词后，ORCA 将打印出一个可直接使用的 %frag 块输入，其中包含所用的碎片指认。这个输入块现在可以随意修改，并用于新的 ORCA 计算。
    

    ===================================================
Orca input for fragment definitions in this run:
===================================================
%frag
 Definition
 1 { 1} end
 2 { 9:10 17:18 21:22 34:37 39:42} end
 3 { 11:13 28:32} end
 4 { 0 3:5 44} end
 5 { 6:7 27 45} end
 6 { 2 8 14:16 19:20 23:26 33 38 43} end
 end
end

    

    例 2：碎片化流程¶
    

    混用 FragProc¶
    

    为了展示我们在例 1 中创建的自定义碎片库的可迁移性，我们现在将其用于一个任意取代的苯，并由一个 DMSO 溶剂分子配位的体系。
    

    

    图：带有 DMSO 溶剂的任意苯衍生物的分子结构。
    

    在 Fragmentator 中可以混用多种碎片化流程。在这个例子中，我们还想为非共价结合的溶剂 DMSO 分子创建一个碎片。因此，我们将添加内置的 FragProc Solvents，它涵盖了大多数常见溶剂分子。
    

    !PBE def2-SVP

%scf
   DryRun true
end

%frag
   PrintLevel 3
   StoreFrags true
   FragProc Extlib, Solvents
   XZYFRAGLIB "CustomLib.xyz"
end

*xyzfile 0 1 structure.xyz

    

    现在可以看到，Fragmentator 成功创建了之前在自定义碎片库中定义的碎片，同时也把 DMSO 溶剂分子识别为单独的碎片。
    

    

    图：任意苯衍生物与识别出的碎片的叠合图（空间填充模型）。
    

    使用 Delete 的高级流程¶
    

    要创建更复杂的碎片化级联，删除先前定义的碎片化流程会很有用，这样就可以用不同的流程重新指认碎片。这可以通过 Delete 功能实现。为演示其功能，我们将以两种不同的方式对 2-苯基吡啶（2-phenylpyridine）进行碎片化。
    

    首先，我们定义一个包含吡啶基（pyridinyl）碎片的外部碎片库 ExtLib.xyz。

    接下来，我们在一个碎片化流程中使用这个外部库，该流程：
    

      

    1. 保护吡啶基碎片（ExtLib）。
      2. 

    2. 应用 FragProc FunctionalGroups，检测出苯基（phenyl）碎片。
      3. 

    3. 应用 FragProc Atomic，此时它不起作用，因为吡啶基和苯基碎片都已被指认。
      4. 

    

    !PBE def2-SVP

%scf
   DryRun true
end

%frag
   StoreFrags true
   FragProc ExtLib, FunctionalGroups, Atomic
   XZYFragLib "ExtLib.xyz"
end

*xyzfile 0 1 struc.xyz

    

    

    图：2-苯基吡啶与所指认碎片的叠合图（空间填充模型）。
    

    现在，我们在 FragProc FunctionalGroups 之后加入 FragProc DelExtLib，以解除对吡啶基的保护，使其可以被后续的 FragProc Atomic 处理。
    

    !PBE def2-SVP

%scf
   DryRun true
end

%frag
   StoreFrags true
   FragProc ExtLib, FunctionalGroups, DelExtLib, Atomic
   XZYFragLib "ExtLib.xyz"
end

*xyzfile 0 1 struc.xyz

    

    如下所示，吡啶基现在被完全碎片化为单个原子。
    

    

    图：使用 Delete 功能时，2-苯基吡啶与所指认碎片的叠合图（空间填充模型）。
