    ORCA 与外部方法（External Methods）¶

    尽管 ORCA 拥有大量电子结构模型（electronic structure models），但它无法覆盖所有可用的方法。因此，ORCA 提供了一个 外部方法接口（interface to external methods），允许你将 ORCA 的优化基础设施与外部程序提供的电子结构方法和 模型势（model potentials）一起使用。这样一来，你就能在 ORCA 基础设施中利用最新的基于 MNDO 的半经验方法（semi-empirical methods）如 PM7，或 神经网络势（neural network potentials）如 AIMNet2 和 UMA，例如用于优化结构、用 NEB-TS 搜索过渡态（transition states），或用 GOAT 采样构象（conformers）。

    外部方法基础设施可以通过 ORCA 简单输入关键词 !ExtOpt 访问，该关键词可以与其他常用关键词 （如 !Opt 或 !GOAT）组合使用。由于每个程序的输出通常具有不同的格式和风格，因此需要单独的包装脚本（wrapper scripts）来连接 ORCA 及其外部优化器基础设施。包装脚本的完整路径可通过 %method 模块提供：

    ! ExtOpt

%method
  ProgExt "/full/path/to/wrapperscript"
  Ext_Params "optional command line arguments"
end

    Ext_Params 关键词用于设置特定于程序的选项，如方法、模型或溶剂化。通过以 -h 标志调用相应的脚本（例如 oet_mopac -h）可以获取各包装脚本的可用选项详细列表。

    重要 部分包装脚本及其用法可以在我们的 ORCA-External-Tools GitHub 仓库中找到。该仓库向社区开放，非常欢迎贡献！

    注意 请注意，根据你的操作系统和基础设施，你可能需要对包装脚本做一些修改！

    注意 对于通过 Python 接口导入的方法（如 AIMNet2 和 UMA），可以使用两种不同的脚本。一种是独立脚本，由于大量导入可能会使你的计算变慢。另一种是服务器/客户端（server/client）方式。这里必须事先用相应的脚本启动服务器，然后客户端脚本就可以像其他脚本一样使用。更多信息见以下示例或 GitHub 上相应的 README 文件。

    官方包装脚本¶

    ORCA-External-Tools GitHub 仓库为 MOPAC 和 g-xTB 等程序以及 AIMNet2 和 UMA 等神经网络势提供了若干开箱即用的脚本。它还包含一个可以快速实现新方法的框架。

    安装¶

    仓库中包含一个 install.py，可简化安装过程。运行它会创建一个默认名为 .venv 的虚拟环境（virtual environment），其路径此后不应更改。此外，还会创建一个默认名为 bin 的文件夹，其中包含所有可与 ORCA 一起使用的可执行脚本。如果需要，这些脚本可以移动到其他位置。 你可以在安装过程中自定义虚拟环境路径和脚本目录：

    python install.py --venv-dir <path/to/venv/dir/> --script-dir <path/to/script/dir/>

    如果你想使用基于 Python 的方法（如 AIMNet2、UMA 或 MLatom），可以添加 -e 标志来安装所需的依赖项：

    python install.py -e aimnet2
python install.py -e uma
python install.py -e mlatom

    由于这些软件包可能存在不兼容的依赖项，建议通过指定不同的虚拟环境和脚本目录为每个软件包分别安装。

    注意 如果你维护多个环境，请记住在安装时显式设置脚本路径。否则，该过程可能会覆盖现有脚本。

    示例 1：通过 MOPAC 用 PM7 优化 Disorazol Z1¶

    在本例中，我们将在 ORCA 中优化 disorazol（一种潜在的抗癌药物），使用 MOPAC 中 PM7 方法生成的能量和梯度。为此，我们只需添加 !Opt 简单输入关键词以及 mopac 包装脚本的额外参数 --method PM7：

    !ExtOpt Opt PAL4

%method
  ProgExt "/full/path/to/oet_mopac"
  Ext_Params "--method PM7"
end

*XYZFILE 0 1 structure.xyz

    我们现在可以像往常一样通过 orca basename.inp 运行 ORCA 输入文件，外部优化器基础设施将生成两个输出文件：正常的 ORCA 输出 basename.out 和外部程序（这里是 MOPAC）的输出 basename_EXT.out。

    我们现在可以检查 ORCA 输出中的收敛情况，并会找到典型的成功消息：

    ***********************HURRAY********************
                    ***        THE OPTIMIZATION HAS CONVERGED     ***
                    *************************************************

    MOPAC 输出也显示最后一次能量和梯度计算正常执行：

    **                              MOPAC v22.0.6                                **
 **                                                                           **
 *******************************************************************************
 **          Digital Object Identifier (DOI): 10.5281/zenodo.6511958          **
 **    Visit the DOI location for information on how to cite this program.    **
 *******************************************************************************

                              PM7 CALCULATION RESULTS

 *******************************************************************************
[...]
 **********************
 *                    *
 * JOB ENDED NORMALLY *
 *                    *
 **********************

 TOTAL JOB TIME:             0.62 SECONDS

    示例 2：用 MOPAC 的 PM6-D3H4X 进行 NEB-TS¶
    

    在本例中，我们将在 ORCA 中运行 Erker 受阻路易斯对（frustrated Lewis pair，FLP）活化双氢的 NEB-TS 过渡态搜索，使用 MOPAC 中 PM6-D3H4X 方法生成的能量和梯度。PM6-D3H4X 是包装脚本中默认选择的方法。因此，无需进一步
定义方法。
    

    

    图：Erker 受阻路易斯对对双氢的活化。
    

    相应的 ORCA 输入包含 MOPAC 包装脚本 mopac.py 的完整路径和常见的 NEB-TS 输入：
    

    !ExtOpt NEB-TS PAL8

%method
  ProgExt "/full/path/to/oet_mopac"
end

%NEB
  NEB_END_XYZFILE "products.xyz"
  PreOpt true
  NImages 15
END

*XYZFILE 0 1 reactants.xyz

    

    为了连接 ORCA 和 MOPAC，我们将使用可在 ORCA-External-Tools GitHub 仓库中获得的 mopac.py 包装脚本。该脚本的完整路径必须通过 %method 模块中的 progext 关键词定义。
    

    我们现在可以像往常一样通过 orca basename.inp > basename.out 运行 ORCA 输入文件，如果一切设置正确，ORCA 将通过包装脚本调用 MOPAC 来计算能量和梯度，并重新格式化为 ORCA 可读的格式。ORCA 的输出看起来与所选任务（这里是 NEB-TS）使用 ORCA 原生方法完成时完全一样。
    

    NEB-TS 运行成功后，生成的最小能量路径（minimum energy pathway）存储为 basename_MEP_trj.xyz，可以使用多种
图形用户界面之一进行可视化，并绘制相对能量。
    

    

    图：PM6-D3H4X 水平下的 NEB-TS 最小能量路径与过渡态初始猜测。

    示例 3：用 AIMNet2 进行 GOAT¶
    

    在本例中，我们将使用 GOAT 为抗炎药物布洛芬（ibuprofen）生成构象系综（conformer ensemble）。为此，我们想使用 AIMNet2 以及我们的 ORCA-External-Tools GitHub 仓库中提供的服务器/客户端脚本。
我们首先必须通过执行 oet_server 脚本来启动 AIMNet2 服务器：
    

    oet_server aimnet2 --nthreads 4

    

    服务器运行后，我们就可以通过 ORCA 输入使用 oet_client 客户端：
    

    ! EXTOPT GOAT PAL8

%method
  ProgExt "/full/path/to/oet_client"
end

*XYZfile 0 1 ibuprofen.xyz

    

    

    注意
一旦用 aimnet2 初始化了服务器，它就可以处理不同的模型/参数化。如果所选模型尚不存在，它将被安装到 .venv 目录中。根据你的下载速度，这可能需要几分钟。
    

    

    我们现在可以像往常一样通过 orca basename.inp > basename.out 运行 ORCA 输入文件，如果一切设置正确，ORCA 将通过包装脚本调用 AIMNet2 来计算能量和梯度，并重新格式化为 ORCA 可读的格式。
    

    GOAT 运行成功后，最终的构象系综存储在 basename.finalensemble.xyz 中，可以使用 Avogadro 2 或 ChimeraX 等图形用户界面进行可视化。

    示例 4：用 UMA 进行 NEB-TS¶
    

    在本例中，我们将对 5-（三甲基硅基）-2-甲基-1,3-环戊二烯的 σ 迁移重排（sigmatropic shift）进行 NEB-TS 过渡态搜索。
    

    

    图：5-（三甲基硅基）-2-甲基-1,3-环戊二烯的 σ 迁移重排。
    

    与 AIMNet2 类似，我们使用服务器/客户端设置。因此，我们首先通过 oet_server 启动服务器：
    

    oet_server uma

    

    

    注意
使用 UMA 模型要求你已登录 HuggingFace 账户（huggingface-cli login）并拥有 UMA 仓库的访问权限。
    

    

    然后，我们可以在 ORCA 输入中提供 umaclient.sh 脚本的路径：
    

    !ExtOpt NEB-TS PAL8

%method
  ProgExt "/full/path/to/umaclient.sh"
end

%NEB
  NEB_END_XYZFILE "products.xyz"
  PreOpt true
  NImages 15
END

*XYZFILE 0 1 reactants.xyz

    

    

    注意
一旦用 uma 初始化了服务器，它就可以处理不同的模型/参数化。如果所选模型尚不存在，它将被安装。根据你的下载速度，这可能需要几分钟。
    

    

    我们现在可以像往常一样通过 orca basename.inp > basename.out 运行 ORCA 输入文件，如果一切设置正确，ORCA 将通过包装脚本调用 fairchem 来计算能量和梯度，并重新格式化为 ORCA 可读的格式。ORCA 的输出看起来与所选任务使用 ORCA 原生方法完成时完全一样。
    

    NEB-TS 运行成功后，生成的最小能量路径存储为 basename_MEP_trj.xyz，可以使用多种
图形用户界面之一进行可视化，并绘制相对能量。

    在本例中，我们将使用 g-xTB 对一个氢负离子转移（hydride transfer）反应进行 NEB-TS 过渡态搜索。g-xTB 可执行文件可从 Grimme 实验室获取，在 ORCA 中运行 g-xTB 的包装脚本可从我们的 ORCA-External-Tools GitHub 仓库获取。下载 g-xTB 可执行文件后，必须将仓库中的参数文件添加到主目录 ~/ 或在 ORCA 输入中指定。然后即可通过以下方式启动 NEB 计算：

%method

end

%NEB

END

    编写你自己的脚本¶
    

    如果你想在 ORCA 中使用目前尚不可用的方法，你可以在 GitHub 上提交 issue，或者自己实现。
为了简化这一过程，ORCA-External-Tools GitHub 仓库提供了一个模块化框架。只需实现 ORCA 与你所选方法之间的接口。
    

    添加新方法的步骤：
    

      

    1. 创建一个继承自 BasicSettings 类的新计算器（calculator）类。
      2. 

    2. 重写 calc 例程以定义计算逻辑。
      3. 

    3. 按照现有计算器中提供的示例定义 main 例程。
      4. 

    4. 将你的新计算器添加到 base_calc.py 中的可用计算器列表中。
      5. 

    

    这些计算器通常无需进一步修改即可在所提供的服务器功能上运行。
